Evidence

Each milestone and release gets a record like the ones below, newest first: what is claimed, what was built, where it ran, what was checked, and where the claim stops. Older records stay as they were written.

"Accepted" and "reviewed" on this page mean re-examined by AI model sessions separate from the ones that did the work, not by an independent human (how it is developed). A release is a named internal build with recorded digests; it is not distributed, and nothing here can be downloaded.

Workloads
Stock OpenSSH sessions driving the shell and commands; file transfer of 0 B to 1 MiB; an SQLite store under crash and modeled power-loss injection; and real programs from another project (a journal, a support resolver, a diagnostics tool, a store writer and resolver), each compared with its Linux build.
Limitations
  • Emulation only. Physical hardware qualification: not yet established.
  • Power loss is modeled below the filesystem; no real power was cut and no drive's flush behaviour was tested.
  • One CPU; one operator identity (several sessions are not several users); 16 processes system-wide.
  • Uploads take about 45 to 60 s per MiB under TCG.
  • An interrupted command's children keep running; a later shutdown then ends in an unreaped stop (QEMU status 71) after the file server has committed.
  • No update or rollback of an installed image; no fork, signals, threads, kernel sockets, IPv6, DNS, DHCP, outbound networking, dynamic linking, C programs, or Linux binaries.
