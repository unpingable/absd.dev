Hardware

Physical hardware qualification: not yet established. PLANNED

No physical machine, device, or hardware family is supported. ABSD is qualified only under QEMU; first read-only boots on one physical machine have been observed and are recorded below as observations, not support. This page defines how hardware support will be stated, and lists exactly which emulated configurations are qualified.

Evidence tiers

Each hardware statement names one tier. A higher tier is never inferred from a lower one.

Emulator-qualified
A named emulator configuration (machine type, firmware, device models, CPU flags) passed the stated checks. Says nothing about real devices, even ones the model imitates.
Exact-hardware-qualified
One specific physical machine or device, identified by model, PCI IDs, and firmware version, passed the stated checks with a named ABSD build and workload. Covers that unit's configuration only.
Machine-configuration-qualified
A machine model in a stated configuration (firmware version and settings, fitted devices) passed the checks on more than one unit. Covers that configuration, not the model in general.
Hardware-family-supported
A family of devices (for example, a controller generation across PCI IDs) is supported on the strength of several exact or configuration qualifications and a driver written for the family's documented interface. Stated per family, with its known exceptions.

Emulator-qualified configurations

MILESTONE-QUALIFIED QEMU 8.2 with TCG on one Linux development host, x86-64, one CPU, -cpu max,vendor=GenuineIntel,+rdrand. Release absd-20261003.1 was later qualified on the same host under TCG and KVM, with an IDE disk or one NVMe namespace RELEASE-QUALIFIED; see its record.

ConfigurationWhat passed
Default PC machine (i440fx), SeaBIOS; PIIX IDE disk as primary master (if=ide, raw image); e1000 on user networkingThe operator system: served boot, SSH, file server, commands, durable-state and filesystem crash matrices, operator image. The whole platform check.
q35, OVMF (UEFI), boot image as a USB stick on xHCI, NVMe as the only disk, VGA framebuffer, no serial portThe kernel's boot suite read back from the screen alone; timer interrupts and preemption; NVMe write, flush, and read-back with a test kernel, verified after a fresh boot and a warm reset.
The read-only physical boot image under SeaBIOS and OVMFBoots to the expected screen; with write-requesting options, NVMe and ATA scratch images stay byte-identical and device traces show only identify and read commands.

Device models covered:

  • MILESTONE-QUALIFIED Intel 82540EM network controller model, PCI 8086:100e (QEMU -device e1000). See e1000(4).
  • MILESTONE-QUALIFIED QEMU's NVMe controller model with a 512-byte-block namespace. See nvme(4).
  • MILESTONE-QUALIFIED QEMU's PIIX IDE controller, ATA disk on the primary channel, PIO. See ata(4).
  • MILESTONE-QUALIFIED Firmware: SeaBIOS (legacy boot) and OVMF (UEFI), both through GRUB's Multiboot2 path.
  • MILESTONE-QUALIFIED Timer and interrupts: the legacy 8254 PIT through the 8259 PIC. The local APIC and I/O APIC are not used.

Physical Intel I219 and I225 Ethernet controllers, AHCI SATA, and NVMe namespaces with 4 KiB blocks are not supported UNSUPPORTED. An emulated device model passing is not evidence that the physical device works.
