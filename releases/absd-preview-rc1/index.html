Try ABSD absd-preview-rc1

A binary developer preview for QEMU on a Linux x86-64 host: kernel d208b61bcd48, platform 0fada7ed031b. Unsigned. Standing: published. Not yet reached: outsider-passed. Stages, in order: built, offline-boot-tested, qualified, release-authorized, published, outsider-passed.

What works

  • Boots under QEMU 8.2 with TCG on a Linux x86-64 host, using the release's own helper, absd-try.py. No Rust, Clang, GRUB or source checkout is needed.
  • Your own ed25519 key is enrolled when the machine is created. You log in with stock OpenSSH as the one operator. The guest has one static IPv4 address on QEMU user networking (network.conf(5)) and accepts SSH connections forwarded from 127.0.0.1 on your host; it makes no outbound connections.
  • A small native shell and commands, unmodified uutils programs and ripgrep, a few C programs (sbase and Toybox adaptations, including the line editor ed), and the manual pages, read with man inside ABSD.
  • Files under /home/operator persist across shutdown and reboot. Files are copied byte-exactly over SSH exec; there is no scp or sftp.
  • The QUICKSTART steps were rehearsed end to end, from staged copies of these exact files, in a fresh unprivileged account on one Linux host with TCG: verification, machine creation and key enrollment, SSH login, man, uptime, a file written and read back after a reboot, and clean shutdowns. The staged-file rehearsal did not test public downloads or an outside reader.

What is not in this preview

  • Physical hardware of any kind.
  • IPv6, UDP, DNS, DHCP and outbound connections. There are no kernel sockets. Network capabilities beyond SSH over static IPv4 are under development and are not part of this preview.
  • Upgrading in place or rolling back: the 64 MiB disk cannot hold a second staged release. A newer preview means a new machine; the QUICKSTART says how.
  • fork, signals, threads and job control; users, groups and permission bits; dynamic linking and Linux binaries.
  • A screen editor, a pager, scp or sftp, packages, cron, a GUI.
  • KVM, several CPUs and hosts other than Linux x86-64 with QEMU 8.2 TCG are untested for this preview; the guide uses TCG.

How to try it

Follow QUICKSTART.md from the release (the same bytes, as sealed: copy on this site). In a new empty directory: download the files below and SHA256SUMS, run sha256sum -c SHA256SUMS and python3 absd-try.py verify ., create a machine with your own new key, boot it, and log in over SSH. Stop if either verification fails.

No first-party ABSD source release accompanies absd-preview-rc1: its kernel d208b61bcd4826181bf9f401551ab620d4eabba0 and platform 0fada7ed031bd84e3a469e717c1d0be5dbefedd6 are not published as source. Its download set does include absd-rc1-boot-corresponding-source.tar and absd-rc1-third-party-notices.tar.gz: the exact GRUB and GNU Unifont corresponding-source packages for the boot components, and the third-party notices. The release's NOTICES.md says how to extract and check them. The earlier public source release absd-preview-20261010 remains available (source release).

Limits

These limitations are quoted from the release's MANIFEST.toml, written before publication; the release was published on 2026-10-18.

  • Physical hardware qualification is not yet established.
  • RC1 candidate 12c preview built locally; no public release, outsider acceptance or endurance claim.
  • No source release is bound to these assets (no release source_commit).
  • Exact GRUB and GNU Unifont corresponding source and the third-party binary notices are attached (absd-rc1-boot-corresponding-source.tar, absd-rc1-third-party-notices.tar.gz, NOTICES.md); they are not the first-party ABSD source release.
  • A 64 MiB disk cannot take a second staged release under the current layout; staged upgrade and rollback are not supported in this preview.

Added on this site:

  • The files are unsigned. SHA256SUMS detects corruption; it does not establish who produced the files.

Evidence

  • published: GitHub release absd-preview-rc1

ABSD is an experimental operating system by James Beck, built largely by AI coding agents under the author's direction and not independently audited. Its source is public under Apache-2.0 (source release absd-preview-20261010, what that does and does not establish); it runs under QEMU only, and no physical hardware is supported.
