ABSD Developer Preview 3

Other developer previews: ABSD Developer Preview 2 · ABSD Developer Preview 1.

A binary developer preview for QEMU on a Linux x86-64 host: kernel 0046112efdd8, platform be522e9f9800. Unsigned. Standing: published. Not yet reached: outsider-passed. Stages, in order: built, offline-boot-tested, qualified, release-authorized, published, outsider-passed.

What works

  • Boots under QEMU 8.2 TCG on an Ubuntu 24.04 x86-64 host with the release helper; no compiler or source checkout is needed.
  • Enrolls your own ed25519 key during machine creation and serves the single operator over stock OpenSSH. The login command ignores your SSH configuration, agent and system known-hosts list, and accepts only the host key the helper read from the guest's console.
  • The shell's line editor has Ctrl-K, command-name completion with Tab, and history search with Ctrl-R. man pages its output through more.
  • The disk carries 80 commands, among them make, patch, diff, sed, find, tar, rg, more, sponge, sysinfo, why and logs.
  • Files and the SSH host key persist across clean shutdown and reboot.
  • What was rehearsed: a script typed the guide's commands against these exact files under QEMU 8.2.2 with TCG: the digest check and verification, the optional source-list check, enrollment, two boots with the same host key and strict host-key logins, an ed edit kept across the reboot, two clean ACPI S5 shutdowns and disposal. Tab completion and history search are covered by the SSH test matrix of the source tuple, not by that rehearsal. Use by an outside reader without help is unverified, and no rehearsal of the public download has run.

What is not in this preview

  • Physical hardware of any kind.
  • Outbound network connections. An HTTPS fetch client, https-fetch, is installed but not provisioned: this disk has no network grant, no pinned issuer and no server list for it, so it refuses every URL. It does not use a public certificate store.
  • A C compiler in the guest (/bin/cc is absent) and a host development kit.
  • Upgrading from Developer Preview 2; a new preview means a new machine.
  • getopts, local and command builtins in absd-sh, and path, option and variable completion; Tab completes command names only.
  • KVM, more than one CPU, and recovery after a crash.

How to try it

Follow QUICKSTART.md from the release (the same bytes, as sealed: copy on this site). Download SHA256SUMS, SHA256SUMS.source, QUICKSTART.md and absd-preview-3-operator.tar.gz (13,066,764 bytes) into one directory. The guide's first command checks SHA256SUMS against a digest obtained apart from the download. That digest is:

016e3fdf2b9345df1e04bc2ee4e4bf18afe5cd81330cd074eb55cd43620e9831

The same command then checks the downloaded files against that list, unpacks the kit, checks the kit's own list and runs python3 absd-try.py verify .; each step runs only if the one before it succeeded. After that you create a machine with your own new key, boot it, and log in over SSH.

The other 9 files are the source and notice archives listed in SHA256SUMS.source (81,477,334 bytes together). They are not needed to run the preview.

Host tools

Use an Ubuntu 24.04 x86-64 host with QEMU 8.2, Python 3.11 or newer, the OpenSSH client and GNU coreutils: sudo apt-get install qemu-system-x86 python3 openssh-client coreutils. The guide uses --accel tcg, QEMU's software emulation, which is what the kit was tested with. KVM is outside this preview. Newer QEMU versions are untested; the helper does not check the QEMU version, so it does not refuse them.

Headless boot and SSH

The guest runs without a graphical display. Keep absd-try.py boot running in one host terminal. After it prints READY, check the host-key fingerprint as the guide says and use the printed SSH command in a second terminal on the same host. On a remote host, use two SSH sessions to that host for these terminals; the guide's 127.0.0.1 address refers to that host.

Limits

These limitations are quoted from the release's MANIFEST.toml, written before publication; the release was published on 2026-11-28.

  • Physical hardware qualification is not yet established.
  • No rehearsal of these exact media is recorded in this manifest. Use by a reader without help is unverified.
  • QEMU operator/core. Native C compiler and host SDK are outside this kit.

Added on this site:

  • Experimental absd-preview-3; this is not for production, and there are no stability or security guarantees.
  • The documented preview boot path uses local QEMU TCG, SeaBIOS and an IDE disk.
  • An unclean stop can require recovery before writable operation resumes; the guide does not cover it.
  • https-fetch takes its TLS randomness from the CPU's RDRAND instruction, which is not a production entropy claim.
  • No reconstruction from the published source archive alone was run, and nobody outside the project has reproduced the build. Byte-for-byte reproduction is not claimed.

Evidence

  • published: ABSD Developer Preview 3 release

ABSD is an experimental operating system by James Beck, built largely by AI coding agents under the author's direction and not independently audited. Its source is public under Apache-2.0 (source release absd-preview-20261010, what that does and does not establish); it runs under QEMU only, and no physical hardware is supported.
