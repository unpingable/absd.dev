ABSD — An experimental operating system.

ABSD is a small operating system, written in Rust, built to find out what a system looks like when isolation, authority, and failure are stated explicitly and checked. It boots, runs isolated processes, keeps files across reboots, runs ordinary Rust programs, and is administered over stock OpenSSH.

Current qualification: single-operator system under QEMU. It is not production-ready, and no physical hardware is supported.

What distinguishes it

Isolation
Every program is a separate process in its own address space, started by spawn; there is no fork. A process sees only itself and its own children. SSH sessions are isolated from one another. Design: spawn, not fork.
Explicit authority
A process can touch only what it was handed: handles to kernel objects, each carrying rights that can be dropped and never added. There are no user IDs and no ambient privilege. This is the capability model of earlier systems, not a new invention. Design: handles and rights.
Bounded scheduling and recovery
Limits are fixed and stated rather than discovered under load: 16 processes in the whole system, four SSH connections. Processes are preempted by a timer; a fixed-priority periodic scheduling class exists as an experiment, with no real-time guarantee. On the main development line (not in a release), a failure of the SSH or file server after the system has come up is answered by a whole-machine reset at most three times; the fourth stops the machine and names the reason. A restart is never counted as a recovery. Design: replacement is not recovery.
Evidence-oriented engineering
Every statement on this site carries a label saying how strongly it is supported, in which environment, and where the claim stops. Failed runs stay on record. How statements are labelled.
